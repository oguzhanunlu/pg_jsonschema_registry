# pg_jsonschema_registry v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A pgrx extension that stores named, versioned, immutable JSON Schemas in the database and validates `jsonb` against them with compile-once, per-backend cached validators.

**Architecture:** Rust/pgrx extension. Schemas live in three extension-owned tables in a `jsonschema` schema. Validation uses the `jsonschema` crate's in-place `Jsonb` representation; `$ref` between stored schemas resolves through a `Retrieve` implementation backed by SPI. A per-backend `thread_local!` cache of compiled validators is cleared by a relcache invalidation callback that `register`/`unregister` trigger via `CacheInvalidateRelcacheByRelid`, so coherence rides on Postgres's own transactional invalidation.

**Tech Stack:** Rust stable (1.99), pgrx `=0.19.3`, `jsonschema = 0.59` (no default features; `jsonb`, `arbitrary-precision`), `serde_json`, PostgreSQL 15–18, `cargo pgrx test` (`#[pg_test]`), `postgres` crate for multi-session tests, Docker for the benchmark.

**Spec:** `docs/superpowers/specs/2026-10-20-pg-jsonschema-registry-design.md`

## Global Constraints

- `pgrx = "=0.19.3"`, `pgrx-tests = "=0.19.3"` (dev). The installed `cargo-pgrx` is 0.19.3 and must stay in lockstep.
- `jsonschema = { version = "0.59", default-features = false, features = ["jsonb", "arbitrary-precision"] }`. No HTTP, no filesystem resolution, ever.
- Cargo features `pg15`, `pg16`, `pg17`, `pg18`; `default = ["pg18"]`. Local development and tests run on the Homebrew PostgreSQL 18 registered in `~/.pgrx/config.toml`.
- Every SQL object lives in schema `jsonschema`. Functions are `strict`, `parallel_safe`; readers are `stable`, writers (`register`, `unregister`) are `volatile`. No `SECURITY DEFINER` anywhere. No extension-created roles.
- Validation functions take the document FIRST: `(doc jsonb, name text, version int)`.
- Error SQLSTATEs: invalid input `22023` (`ERRCODE_INVALID_PARAMETER_VALUE`), unknown schema `42704` (`ERRCODE_UNDEFINED_OBJECT`), duplicate `$id` `42710` (`ERRCODE_DUPLICATE_OBJECT`), dependents exist `2BP01` (`ERRCODE_DEPENDENT_OBJECTS_STILL_EXIST`), document invalid in `validate` `23514` (`ERRCODE_CHECK_VIOLATION`).
- License: PostgreSQL License (already in `LICENSE`). Code copied from pg_jsonschema (Apache-2.0) is not allowed; its `raw.rs` is a reference for the pattern only.
- Commit messages end with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.
- SPI queries always schema-qualify tables (`jsonschema.registry`), never rely on `search_path`.

## Review Focus

1. **Boolean schemas** (`true` / `false` are valid draft 6+ schemas, have no `$id`, and are not JSON objects): `register('any', 'true')` must succeed and `valid('{}', 'any', 1)` must be true. Test pinned in Task 4.
2. **Cross-schema `$ref` with a fragment** (`"$ref": "https://acme.example/address#/$defs/street"`): the retriever is asked for the base URI and the fragment is resolved inside it. Tests pinned in Task 3 (ref recorded) and Task 5 (validation through the fragment).
3. **TOASTed documents**: a document column large enough to be compressed/out-of-line must validate through `pg_detoast_datum_packed` without corruption. Test pinned in Task 5.
4. **Unregister in a warm backend**: after `valid` has cached a schema, `unregister` in the same backend must make the next `valid` raise `42704`, not answer from the cache. Test pinned in Task 5.
5. **Bad identifiers**: empty `name`, `version <= 0`, and `version` not above the current maximum must all raise `22023` with a message naming the rule. Test pinned in Task 4.

```sql
CREATE SCHEMA jsonschema;
GRANT USAGE ON SCHEMA jsonschema TO PUBLIC;

CREATE TABLE jsonschema.registry (
    id          bigint      GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name        text        NOT NULL CHECK (name <> ''),
    version     int         NOT NULL CHECK (version > 0),
    schema      jsonb       NOT NULL,
    draft       text        NOT NULL,
    created_at  timestamptz NOT NULL DEFAULT now(),
    created_by  text        NOT NULL DEFAULT current_user,
    UNIQUE (name, version)
);

CREATE TABLE jsonschema.ids (
    uri        text   PRIMARY KEY,
    schema_id  bigint NOT NULL REFERENCES jsonschema.registry(id) ON DELETE CASCADE
);

CREATE TABLE jsonschema.refs (
    schema_id  bigint NOT NULL REFERENCES jsonschema.registry(id) ON DELETE CASCADE,
    ref_id     bigint NOT NULL REFERENCES jsonschema.registry(id),
    PRIMARY KEY (schema_id, ref_id)
);
CREATE INDEX refs_ref_id_idx ON jsonschema.refs (ref_id);

CREATE VIEW jsonschema.schemas AS
SELECT r.name, r.version, r.draft, i.uri AS id_uri, r.created_at, r.created_by,
       (SELECT array_agg(d.name || '/' || d.version ORDER BY d.name, d.version)
          FROM jsonschema.refs f JOIN jsonschema.registry d ON d.id = f.ref_id
         WHERE f.schema_id = r.id) AS refs
  FROM jsonschema.registry r
  LEFT JOIN jsonschema.ids i ON i.schema_id = r.id;

GRANT SELECT ON jsonschema.registry, jsonschema.ids, jsonschema.refs, jsonschema.schemas TO PUBLIC;

SELECT pg_catalog.pg_extension_config_dump('jsonschema.registry', '');
SELECT pg_catalog.pg_extension_config_dump('jsonschema.registry_id_seq', '');
SELECT pg_catalog.pg_extension_config_dump('jsonschema.ids', '');
SELECT pg_catalog.pg_extension_config_dump('jsonschema.refs', '');
```

### Task 4: `jsonschema.register`

**Files:**
- Create: `src/api.rs`
- Modify: `src/lib.rs` (add `mod api;`)

**Interfaces:**
- Consumes: `registry::*`, `compile::compile`.
- Produces, in `#[pg_schema] mod jsonschema` inside `src/api.rs`:
  - `#[pg_extern(volatile, strict, parallel_unsafe, name = "register")] fn register_next(name: &str, schema: pgrx::JsonB) -> i32`
  - `#[pg_extern(volatile, strict, parallel_unsafe, name = "register")] fn register_version(name: &str, version: i32, schema: pgrx::JsonB) -> i32`
  - private `fn do_register(name: &str, version: Option<i32>, schema: serde_json::Value) -> i32` implementing the spec's rules in this order: reject empty name (22023); `registry::lock_for_register()`; compute `max = registry::max_version(name)`; `version` = `max + 1` or the given one, which must be `> max` and `> 0` else `22023` with message `"version must be greater than N"` / `"version must be positive"`; `jsonschema::meta::validate(&schema)` else `22023` `"invalid JSON Schema: <err>"`; `compile::compile(&schema)` else `22023` `"cannot compile schema: <err>"`; `registry::insert_schema`; if `schema` is an object with a string `$id`, `registry::insert_id(id, row_id)` else `42710` with the returned message; for each `ref` in `compiled.refs` not equal to the new id, `registry::insert_ref`; return version.
  - Errors are raised with `ereport!(ERROR, PgSqlErrorCode::ERRCODE_..., message)`.
